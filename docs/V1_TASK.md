# 开发任务：Windows 微信聊天记录导出工具 V1.0

## 一、你的角色与工作方式

你是一名资深 Python 桌面应用工程师，负责基于现有开源项目完成二次开发。

请遵循以下原则：

1. **先阅读源码，理解现有实现，再修改代码。**
2. 优先复用原项目已经验证的数据库读取、消息解析、媒体处理及导出逻辑。
3. 以轻量化、稳定性、可维护性为主要目标。
4. 不要过度设计，不引入不必要的框架。
5. 不需要为了使用 Java 而重写现有 Python 实现。
6. 不要停留在设计、伪代码或 TODO 阶段，需要完成实际编码、测试和构建。
7. 遇到无法验证的功能，明确说明，不要声称已经实现。
8. 每个开发阶段结束后执行相关测试，避免破坏原项目已有功能。

**底层依赖：**

## 三、V1.0 开发目标

将现有“输入好友昵称或群名进行导出”的交互方式，升级为：

**启动程序 → 识别微信数据目录 → 加载联系人与群聊列表 → 搜索及勾选 → 设置导出选项 → 批量导出 → 查看结果。**

核心要求：

- 用户无需手动输入准确的联系人名称。
- 支持好友和群聊分类。
- 支持搜索、单选、多选、全选和取消选择。
- 支持一次导出多个会话。
- 保留原来的 TXT、Markdown、JSON 导出能力。
- 保留已实现的图片、普通文件导出。
- 提供导出进度、异常提示及结果汇总。
- 保留聊天记录预览功能。
- 打包为独立 EXE。
- 不依赖云服务，不上传聊天记录。

## 四、功能详细要求

### 4.1 微信运行状态与数据目录

程序启动后：

1. 检测微信进程是否正在运行。
2. 尝试自动识别微信数据目录。
3. 检查路径有效性及支持的数据库文件是否存在。
4. 检测失败时允许用户手动选择目录。
5. 在界面中显示当前数据源状态。

参考现有 `wechat_data_dirs.py`。

不要在每次切换 UI 标签页时重复进行数据目录扫描。

注意：Windows 磁盘根目录、中文路径、空格路径及多个微信账号目录需要妥善处理。

### 4.2 好友及群聊列表（本次重点）

在主界面增加聊天列表区域。

功能要求：

- 显示本地已有聊天记录的好友和群聊。
- 支持“全部 / 好友 / 群聊”分类。
- 支持按备注名、昵称、群名称搜索。
- 显示联系人或群名称、会话类型、最近消息时间（可获得时）。
- 每个会话提供复选框。
- 支持多选、全选当前筛选结果、取消选择。
- 切换分类和搜索条件时，保留用户此前的选择。
- 显示当前选择数量。
- 支持手动刷新列表。

**关键设计要求：**

必须使用微信内部稳定的 `username` 作为会话唯一标识，不允许仅使用昵称作为唯一键，因为不同好友可能重名。

优先复用现有 `_batch_chat_candidates()` 及相关联系人映射逻辑。

只列出能可靠关联到本地消息记录的会话。

如果有无法确定身份的消息表，记录其数量并给予提示，不允许猜测归属。

首次加载列表时只读取必要的会话元数据，不允许为显示联系人列表而扫描所有消息正文或导出全部聊天。

### 4.3 批量导出功能

新增支持按 `username` 集合导出指定会话的能力。

建议接口：

`export_selected_chats(usernames, options, progress, cancel_token)`

具体签名可根据项目实际架构调整。

要求：

1. 可以只导出一个会话，也可以导出多个会话。
2. 批量任务共享本次数据库访问上下文，避免反复初始化数据库解密过程。
3. 复用已有 `_export_chat_impl()` 等成熟导出逻辑。
4. 每个会话建立独立输出目录。
5. 重名会话不会覆盖彼此导出的文件。
6. 某个会话失败，不影响其他会话继续导出。
7. 导出结束后生成任务汇总。
8. 保证消息发送者、时间、顺序和群聊归属准确。

保留原有“导出全部聊天”能力作为独立操作，不允许因新增选择性导出而破坏它。

### 4.4 导出格式和设置

主界面提供以下设置：

**导出格式（允许多选）：**

- TXT
- Markdown
- JSON

**媒体选项：**

- 图片
- 普通文件附件

**其他设置：**

- 输出目录
- 导出前检查目标目录
- 导出完成后打开文件夹

V1.0 暂时不需要新增 Excel、PDF 或交易统计功能。

不强制所有格式同时生成，应按用户勾选的格式输出，以减少不必要的磁盘写入。

### 4.5 导出进度与任务管理

导出必须在后台工作线程中运行，不允许阻塞 Tkinter 主线程。

优先复用现有 `threading + queue + Tkinter.after()` 机制。

界面显示：

- 当前正在导出的会话名称。
- 已完成会话数 / 总会话数。
- 当前阶段，例如读取消息、处理附件、写出文件。
- 已成功导出的消息数（如果可以可靠获取）。
- 当前任务执行状态。
- 失败数量及失败原因。
- 任务取消按钮。

取消功能要求：

- 采用协作式取消机制。
- 在会话之间检查取消状态。
- 能安全增加取消检查点的内部循环，也应支持取消。
- 不允许粗暴结束线程或破坏数据库连接。
- 取消时仍需执行临时资源清理。
- 已成功写出的文件应按明确规则保留，未完成文件应标记或清理，避免误认为完整导出。

### 4.6 聊天记录预览

保留并优化已有预览功能。

V1.0 只需：

- 展示联系人或群聊名称。
- 按时间顺序显示聊天。
- 区分自己和其他发送者。
- 显示图片和文件的可用状态。
- 能打开已导出的聊天记录。

优先复用 `preview.py`，不要另造一套复杂的网页聊天系统。

对大量记录采用按需加载或分页显示，避免一次性渲染整个会话。

## 五、界面设计要求

建议采用简单的双栏式桌面界面：

左侧：

- 分类切换
- 搜索框
- 联系人/群聊列表
- 勾选状态
- 全选/取消选择

右侧：

- 导出格式
- 附件选项
- 输出路径
- 导出按钮
- 导出进度和日志

整体要求：

- Windows 原生桌面风格。
- 排版简洁，操作直观。
- 控件间距统一。
- 支持窗口调整大小。
- 长联系人名称合理截断或滚动显示。
- 不出现布局重叠。
- 不需要复杂动画。
- 不使用 Electron、WebView 或独立前端服务。
- 尽量不增加新的第三方 GUI 依赖。

如果 Tkinter + ttk 能实现需求，不要额外引入 GUI 框架。

## 六、架构与代码修改要求

优先对现有代码做增量修改。

建议拆分的模块：

- `chat_list_service.py`：会话列表查询与搜索。
- `export_task_service.py`：选择性批量导出与任务管理。
- `ui/chat_list.py`：联系人列表界面。
- `ui/export_panel.py`：导出选项界面。

但请先检查实际代码规模和依赖关系。如果拆分会显著增加复杂度，可以选择更少的模块。

不要为了符合建议目录而机械重构。

重点保持以下原则：

1. 数据库访问逻辑与 GUI 分离。
2. GUI 不直接拼接 SQL。
3. 联系人列表和消息读取分离。
4. 导出选项采用明确的数据结构。
5. 导出任务状态有清晰的生命周期。
6. 后台线程不能直接更新 Tkinter 控件。
7. 保留可测试的 CLI/服务入口。

## 七、轻量化要求

轻量化包括：

- EXE 文件大小。
- 程序冷启动速度。
- 空闲内存占用。
- 扫描联系人时的响应速度。
- 批量导出的内存使用。
- 第三方依赖数量。

优先沿用现有 PyInstaller 打包流程。

语音识别、视频增强等不属于 V1.0 开发范围。

允许评估将 SenseVoice、FFmpeg 等大型可选功能移出核心打包，但必须先检查依赖关系。

**不允许因为删除依赖而破坏现有数据库读取、普通聊天导出、图片及文件处理功能。**

先建立原版构建基线，再实施精简，并对比修改前后的实际数据。

不要求使用 `--onefile` 作为唯一方案；可比较 `--onefile` 和 `--onedir`，但正式交付优先提供用户可直接启动的 EXE。

## 八、数据安全要求

本项目处理用户私人聊天记录，必须遵守：

1. 全程本地运行。
2. 不上传聊天记录。
3. 不自动收集或发送数据库密钥。
4. 只操作用户自己有权访问的数据。
5. 原始微信数据库只读。
6. 保留原项目的敏感临时目录隔离与清理机制。
7. 异常或取消任务时也尽力清理敏感缓存。
8. 不在日志中输出聊天正文或数据库密钥。
9. 不将真实聊天记录、数据库或密钥提交到 Git。
10. 不为简化实现而关闭 Windows Defender、SmartScreen 或其他安全保护。

不新增进程注入、额外密钥提取或绕过微信安全机制的代码。沿用现有经过实际验证的读取接口，并明确其兼容性及合规风险。

## 十、测试与验收标准

开发完成后至少验证：

### A. 联系人及群聊

- 能成功识别本地已有聊天的联系人。
- 能区分单聊和群聊。
- 能搜索备注及群名称。
- 能选择多个会话。
- 能处理重名联系人。
- 切换分类和搜索后不会丢失选择状态。
- 无会话、无搜索结果、目录不可访问时有合理提示。

### B. 导出

- 单个会话正常导出。
- 多个会话批量导出。
- 导出 TXT、Markdown、JSON。
- 只选择一种格式时不会生成其他格式。
- 图片和文件导出不退化。
- 不同会话目录不会冲突。
- 某个会话失败后能正确汇总结果。
- 原有全部导出功能仍然可用。

### C. 稳定性

- 扫描和导出期间 GUI 不冻结。
- 多次刷新联系人列表不会导致数据重复。
- 重复点击导出不会启动冲突任务。
- 取消任务后资源正常释放。
- 任务异常后可以再次执行。
- 敏感缓存清理机制仍然正常。

### D. 构建

- Python 单元测试通过。
- PyInstaller 构建成功。
- EXE 在目标 Windows 环境能运行。
- 不需要单独安装 Python。
- 不依赖额外 Web 服务。
- 保留原项目及第三方许可证声明。

不能在开发环境实际访问用户微信时，应使用模拟 SQLite 数据及测试夹具验证，并将真实微信验证项目单独标注为“待用户验收”。
